# Deliberate shortcuts

Code carries no comments, so known ceilings and upgrade paths live here.

- **CSP**: one static host allow-list with `'unsafe-inline'` for every route, shipped as `Content-Security-Policy-Report-Only`. Compensating controls: no user-supplied HTML, the UPI ID also sent in the WhatsApp message, daily UTR reconciliation. Upgrade: a nonce policy on `/checkout`, `/order` and `/admin` (routes that `await connection()`). Enforce after Playwright shows no violations.
- **OTP enrolment window**: Better Auth's session refresh extends any session to the full 7 days on first read, so a 15-minute `expiresAt` cannot hold. The window is enforced from `session.createdAt` instead (`enrolmentExpired` in `lib/auth.ts`, used by `getAdminSession` and the passkey registration hook). The OTP session row itself lingers until the purge.
- **`auth_event.user_id`** has no foreign key on purpose: events must outlive banned or deleted users.
- **Better Auth CLI and `server-only`**: the `auth` CLI cannot load a config that imports `server-only`. `bun run auth:generate` runs it from `scripts/auth-cli`, whose `tsconfig.json` maps `server-only` to its empty module, with `JITI_FS_CACHE=false` so stale transforms are not reused.
- **`rate_limit` fixed windows**: burst at a window edge accepted.
- **Library majors**: TypeScript 7 waits for typescript-eslint support (`<6.1.0` today); Drizzle 1.0 waits for a stable release.
- **`forbidden()`** still needs the experimental `authInterrupts` flag, so `requireRole` redirects instead of returning 403 pages.
- **Storefront catalogue cache**: `catalog()` in `lib/storefront.ts` loads all active products into one cache entry tagged `catalog`; listings, search, vehicle pages and `/api/catalog-snapshot` filter it in memory. Fine at a few hundred SKUs; split by system once the catalogue passes about 5,000.
- **Sheet history entries**: `useBackToClose` pushes one history entry per open sheet. Following a link from inside an open sheet leaves that entry behind, so Back returns to the same page once before leaving it.
- **Phase 3 interaction gaps**: the desktop cart opens the `/cart` page, not a drawer; cart lines remove through the stepper (bin at the minimum) with Undo, without swipe; the wholesale explainer is static text; typed quantities use a native numeric input. The cart renders in the browser after fetching `/api/catalog-snapshot` (preloaded), so its largest paint is about 3 s on a throttled 4G phone; render the cart on the server from a cookie if that matters.
- **Launch blockers accepted by the owner (23 Nov 2026)**: (1) every legacy photo is shown, including about 90 carrying another seller's "elyf evspare" watermark (`lib/storefront.ts` orders own photos first but no longer filters); replace them from the "Photos to sort" view before `SITE_INDEXABLE=true` and before any Merchant Center feed. (2) Add to cart shows on every active product that is not out of stock (`Tile.purchasable = stock !== 0`); the legal check `isPurchasable` now only gates Product JSON-LD (`Tile.compliant`). Country of origin, importer and price approval must be filled before launch; restore `isPurchasable` as the buy gate in `placeOrder` at Milestone A.
- **Photo review of the 32 multi-photo products (26 Nov 2026), no data changed**: exact duplicates to remove: product 254 photo 347; product 390 photos 538, 539, 540. The owner checked the photos that looked like a different part on products 364, 245, 268, 324, 375, 384 and 389: all correct, keep them. Shop's own photos (no watermark) still marked unsorted: 296, 300, 301, 410. Remove or mark them in each product's Photos section.
- **Early checkout (Milestone A slice)**: `placeOrder` handles pickup and Maharashtra courier with `pay_at_store` or `upi_manual` only. Courier fees come from the Shop settings bands; above the last band the order lands in `quote_pending` until staff enter the charge. Each placed order emails the shop (`after()` in `placeOrder`) once `GMAIL_USER`/`GMAIL_APP_PASSWORD` are set; until then the shop sees orders only in the admin or when the customer sends the WhatsApp message. Not built: shelf-check screen, cash memos, hold-expiry cron, customer emails, one-time order links (the order page opens only with the cookie set at checkout), BotID.
- **Stock is reserved on confirmation, not at checkout**: `placeOrder` refuses quantities above the stock it sees but does not decrement it; `confirmOrder` locks the rows, decrements and refuses when stock ran out. Two customers can therefore place orders for the last piece; the second confirm fails and staff tell that customer. This closes stock hoarding by unconfirmed orders without a hold-expiry job.
- **PGlite in tests is one session**: `@electric-sql/pglite-socket` multiplexes every connection over a single session, so concurrent transactions are not isolated. Tests run serially and never race two orders; concurrency checks need a real Postgres.
- **Product copy (23 Nov 2026)**: names, specs and descriptions of all 206 products were rewritten from the old catalogue's own names and codes plus general facts about each part type, and marked reviewed. The previous values are in `audit_log` (`action = 'content'`, one row per product, `diff` holds old and new). Shop words the drafts could not decode ("Ullu", "TUNW", "+2D") were kept as written; the owner should confirm them in the product editor.
- **Test builds run on one CPU**: `BUILD_CPUS=1` (`next.config.ts` `experimental.cpus`) because the in-process PGlite socket server used by `e2e/db.ts` and CI drops connections when 11 build workers each open a pool. Production builds against Neon keep full parallelism. A Postgres service container in CI would remove this.
- **Policy pages are drafts**: `scripts/policies.ts` (seeded with `bun run seed:content`, never overwriting) was written from the plan's decisions. The 2-day and 7-day return windows and the 3-day pickup hold need the owner's and a lawyer's review before launch; there is no admin page editor yet, so edits go through the `page` table.
- **Country of origin and importer removed (owner, 25 Nov 2026)**: no longer asked for in the admin, shown on product pages or required by `purchasableIssues`. The columns (`country_of_origin`, `maker_address`) stay in the database. The Consumer Protection (E-Commerce) Rules 2020 and Legal Metrology rules expect country of origin for imported goods sold online; restore the field before scaling if a lawyer advises it.
- **Vehicle tags from research (25 Nov 2026)**: every tag added from online research is `verified = false` with its evidence in `product_vehicle.source`; the shop shows "Sold for" until staff mark it Fits in the product panel (list view "Vehicles to check").
